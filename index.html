I build cross-layer systems for predictable and efficient LLM inference.

  1. Layer 1 · Requests & SLOs

    Which request should run next?

    Requests arrive with latency targets, their service-level objectives (SLOs), and some wait in the queue close to missing them. Choosing what runs next is a decision under uncertainty, because no one knows in advance how long each response will be.

    Sharing GPUs among LLM workloads

  2. Layer 2 · Serving runtime

    How should one GPU be divided?

    The serving engine batches requests and keeps each one’s state in GPU memory, allocating pages as requests arrive and freeing them as they finish. I work on the scheduling layer beneath engines like this, which divides one GPU among several workloads.

    Sharing GPUs among LLM workloads

  3. Layer 3 · GPU execution

    Which code actually sets the speed?

    Once a request and its data arrive, kernels run across the GPU’s parallel lanes. A profiler shows where the time goes, but not which change would make the whole application faster; causal analysis estimates that by experimenting on the running program.

    Causal performance analysis for GPU programs

  4. Layer 4 · Memory & storage

    Who should move the data?

    Models and their data increasingly outgrow GPU memory, so blocks must stream in from SSDs. Whether the CPU or the GPU controls that movement shapes how quickly data arrives, and I compare these designs on the same machine.

    Moving data from storage to GPU memory
